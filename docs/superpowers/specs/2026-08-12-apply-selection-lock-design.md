# 投递岗位选择锁定设计

## 背景

小鹏投递链路依次经过岗位列表、岗位详情和申请表单。列表页与详情页可能同时保留在浏览器标签页中。现有监听器使用一个全局详情状态轮询所有标签页，导致列表页与旧详情页交替覆盖当前岗位；重新生成后，监听器仍使用启动时的简历路径，后续表单无法上传新文件。

## 目标行为

1. 用户点击岗位卡片后，助手把随后打开的具体岗位详情视为当前候选岗位。
2. 用户在具体岗位详情页点击“立即投递”“投递简历”“去投递”或“申请职位”时，助手锁定该详情页对应的岗位。
3. 后台保留的列表页和旧详情页不能覆盖已锁定岗位；用户在另一个详情页再次点击投递时，新岗位取代旧岗位。
4. 简历根据锁定岗位的标题和 JD 生成。生成期间若用户切换并投递新岗位，完成后按最新锁定岗位再生成一次。
5. 申请表单出现后自动填写非敏感字段，并使用当前会话最新生成的简历上传。助手永远不点击最终提交按钮。

## 设计

监听器为每个页面分别保存详情指纹，不再用一个 URL/文本变量跨标签页比较。浏览器侧记录真实用户点击的岗位卡片与投递按钮；投递按钮点击会携带当时的详情 URL、标题和页面正文，在页面跳转前同步回传给 Node 侧。

仪表盘会话分别保存 `selectedDetailPage` 与 `formPage`。简历生成从锁定详情快照读取标题和 JD，上传目标优先使用表单页。监听器的简历路径改为可更新状态：每次生成完成后更新路径，后续轮询会自动上传到延迟出现的表单。

## 测试

- 同时存在列表页、旧详情页和新详情页时，只锁定最后一次点击投递的详情，且列表页不会触发详情事件。
- 监听启动时没有简历，后续更新简历路径并打开表单时，文本字段与简历都会自动填写。
- 运行全部 Node 测试，确认既有 ATS 导航、简历生成和仪表盘接口行为没有回归。
